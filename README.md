# The Indian Rub Co. — Android app

A native Android launcher for the live Indian Rub Co. storefront. It loads the public HTTPS site at `https://indian-rub-co-storefront.vercel.app/`, so shoppers see the deployed site rather than a local development server.

## App quality and behavior

- Branded Android launch screen, adaptive launcher icon, page progress and a recovery screen with retry/browser options.
- The splash gives way as soon as the first web content is visible; a stalled network load gets a retry state instead of hanging indefinitely.
- HTTPS-only WebView, mixed content blocked, Safe Browsing enabled where supported, and off-site links opened by Android.
- Android back follows storefront history. The WebView pauses/resumes with the Activity, preserves navigation state, and recovers from renderer failure.
- Layout respects Android system bars and display insets, including modern edge-to-edge devices.

## Build on your computer

1. Install Android Studio (a stable version that supports API 36) and accept the Android SDK licenses.
2. Open this folder in Android Studio and allow Gradle sync. Install JDK 17, Android SDK Platform 36 and Build Tools if prompted.
3. Choose **Build → Build Bundle(s) / APK(s) → Build APK(s)**, or run from PowerShell in this directory:

   ```powershell
   .\gradlew.bat assembleDebug
   ```

4. Find the APK at `app\build\outputs\apk\debug\app-debug.apk`. Transfer it to an Android phone to install it.

## Build with GitHub Actions

A workflow is included at `.github/workflows/android-apk.yml`. Put the **contents of this project folder** in a GitHub repository, with the workflow included, then push to `main` or `master`. GitHub Actions will compile the debug APK and attach it as the `indian-rub-co-debug-apk` artifact to the run (kept for 14 days). You can also start it manually from the repository's **Actions** tab using **Build Android APK → Run workflow**. Download the artifact from the completed run.

The workflow uses GitHub's hosted Linux runner and installs Java 17, Android SDK 36, and Gradle through the wrapper. It does not require Android Studio on your PC. Builds also run for pull requests.

The APK generated by this workflow is a debug APK for testing/sideloading. Google Play distribution needs a signed release bundle and a Play Console listing. Do not put a signing key or passwords into the repository; use GitHub Actions secrets if release signing is configured later.

## Storefront limitation

The supplied website README says there is no backend: carts, order history, coupons and reviews stay in each shopper's browser, and placed orders are not sent to the business. This Android wrapper does not change that. Connect an order backend and confirm prices, products, shipping, contacts and fulfillment before taking real orders.

The site currently sends `noindex, nofollow`, which discourages search engine indexing. The app and people with its direct link can still open it.

## Storefront deployment

The original Vercel project belongs to a teammate. Its public URL was returning the source entry instead of a built JavaScript bundle, so this app points to a separate production copy deployed to the connected Vercel account at `https://indian-rub-co-storefront.vercel.app/`. The copy was built from the supplied website source and includes SPA route fallback. The teammate's project and domain were not changed.
